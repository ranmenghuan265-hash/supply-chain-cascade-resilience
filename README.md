**EN / TL;DR** — A closed-loop framework for cascading failures in emergency supply networks. ## 一、问题：级联失效不是线性退化

应急供应链（灾害救援、应急物资调配）在遭遇冲击时，退化过程具有明显的**相变特征**：失效节点比例越过某个临界点后，网络效率会在极短时间内断崖式下跌。

而现有的干预方法几乎都基于**静态拓扑重要性**（度、中心性）来排序保护对象。这有一个结构性缺陷——拓扑重要性是**不随时间变化的**，而失效风险是**动态的**。一个度很高但当前负载很轻的节点不需要救；一个度中等但已经接近容量上限、且上游刚断供的节点才是引爆点。按静态指标干预，等于永远慢一步。

这项工作要回答的问题是：

> **能不能在节点真正失效之前，识别出它已经进入"临界状态"，并在资源极度有限的条件下决定救谁、怎么救？**

三个子问题对应三个模块：

| # | 子问题 | 模块 |
|---|---|---|
| 1 | 应急场景下的级联失效应该怎么建模才不失真 | 级联失效仿真（同时作为数据生成器） |
| 2 | 能不能提前一步预测节点失效 | DNN-LightGBM 融合预测模型 |
| 3 | 预测出来之后，1% 的预算该怎么花 | 邻域健康度自适应干预策略 |

## 三、级联失效模型规格

### 3.1 响应能力

传统的纯度值负载模型（Motter–Lai 类）忽略了一个现实弹性：**上游供应商多的节点，抗上游断供的能力天然更强**。因此为每个节点定义响应能力

$$R_i = \frac{U_i}{U_{\max}}$$

其中 $U_i$ 为节点 $i$ 的上游邻居数，$U_{\max}$ 为全网最大值。$R_i \in (0, 1]$，后续贯穿负载、容量、失效判定三处。

### 3.2 初始负载与容量

$$L_{0i} = d_i^{\,x} \cdot (1 + \lambda R_i)$$

$$C_{\max,i} = (1 + \beta) \cdot L_{0i} \cdot (1 + \mu R_i)$$

- $d_i$：节点度；$x$：负载对度的敏感指数
- $\lambda$：响应能力对负载的调节系数（上游多 → 承接的任务也多）
- $\beta$：容量冗余系数
- $\mu$：响应能力对容量的调节系数（上游多 → 可动用的替代资源也多）

### 3.3 两阶段负载重分配

节点 $i$ 失效后，其负载**不是**一次性推给下游，而是分两阶段：

**阶段一 —— 下游承接。** 负载按容量余量分配给下游邻居集合 $\Gamma_{out}(i)$。

**阶段二 —— 同层溢出。** 下游吃不下的部分，转给同层 sibling 节点，分配权重系数 $\iota$。

> 这一步是刻意加的。只往下游推会**低估同层替代供应的缓冲作用**——现实中一个供应商挂了，采购方的第一反应是找另一个同级供应商，而不是让下游硬扛。少了这一阶段，仿真会系统性高估级联规模。

**波动与守恒。** 每次分配乘以随机波动因子 $\xi \sim U(0.8, 1.2)$，模拟现实分配的不确定性；随后**对分配结果归一化，使总负载回到重分配前的量**。

> 加了随机性但保住了系统负载守恒。如果不归一化，守恒被破坏后不同轮次、不同策略之间的结果就失去了可比性——策略 A 看起来更好，可能只是它那次波动因子抽得更小。

### 3.4 失效判定：用时间，不用超载

$$B_i = \frac{1}{C_{\max,i}}, \qquad T_i(t) = \frac{L_i(t) \cdot B_i}{R_i}$$

$$T_i(t) > T_{\max} \Rightarrow \text{节点 } i \text{ 失效}$$

$B_i$ 为单位负载处理耗时（容量越大越快），$T_i(t)$ 为当前负载的预计处理时长，除以 $R_i$ 体现上游资源对处理速度的加成。

**$T_{\max} = 48\text{h}$，$T_{\min} = 24\text{h}$。**

> 判据选择是这个模型和通用级联失效模型最主要的区别。通用模型用 $L > C_{\max}$ 判失效，但**应急场景的本质约束是时间，不是容量**——物资晚到 72 小时，节点即使没"爆"，功能上也已经失效了。$T_{\max}$ 取自灾害救援文献公认的 72 小时"黄金救援期"，并收紧到 48h，因为供应链节点需要在黄金期结束前完成交付，而非恰好在终点抵达。

## 四、失效概率预测模型

### 4.1 特征（7 维）

| 特征 | 类型 | 含义 |
|---|---|---|
| RealTimeLoad | 动态 | 当前时刻负载 |
| C_max | 静态 | 节点容量 |
| R | 静态 | 响应能力 |
| OutDegree / InDegree | 静态 | 出/入度 |
| EigenvectorCentrality | 静态 | 特征向量中心性 |
| PageRank | 静态 | PageRank 值 |

**动态量只有 RealTimeLoad 一个**，这是刻意的：判据要从"结构重要性"推进到"状态脆弱性"，就必须让模型学会**结构特征与实时状态的交互项**，而不是靠堆动态特征把答案喂给它。

### 4.2 结构

```
7 维原始特征
     │
     ├──► 预处理：多项式特征扩展 → KNN 缺失值填补 → 标准化
     │         + 高斯噪声 σ = 0.6（模拟真实数据采集误差）
     │
     ├──► LightGBM ──► 提取叶节点路径 ──┐
     │                                  │  concat
     └──────────────────────────────────┤
                                        ▼
                           embedding 层（8 → 36）
                                        │
                                   Dense 128 ── BatchNorm ── Dropout
                                        │
                                   Dense 64  ── BatchNorm ── Dropout
                                        │
                                   Dense 1 (sigmoid) ──► 失效概率 P
                           优化器 Nadam · 超参网格搜索
```

**Stacking：** LightGBM 与 DNN 作基学习器（2:8 划分），LogisticRegression 作元学习器。

> **为什么用叶节点路径而不是直接拼 LightGBM 的预测值**：树模型的叶节点路径本身编码了一组**离散的特征交叉规则**（"度 > a 且负载 > b 且中心性 < c"），把它作为 embedding 输入给 DNN，相当于让神经网络在树学到的特征交叉空间上继续做连续拟合。只拼预测值会丢掉这层交叉信息。这是 GBDT + LR / GBDT + NN 一类做法在这个问题上的应用。

## 五、马尔可夫状态演化

把预测出的失效概率 $P_i$ 直接作为转移概率，构造单节点两态转移矩阵：

$$M_i = \begin{bmatrix} 1 - P_i & P_i \\ 0 & 1 \end{bmatrix}$$

第二行为 $[0, 1]$，即**失效态是吸收态**——节点一旦失效不会自行恢复。这符合应急场景（受损节点的恢复需要外部干预，不是自发的）。

系统层面按失效节点比例划分四态：

| 状态 | 失效节点比例 |
|---|---|
| Healthy | < 30% |
| Moderate | 30% – 60% |
| Severe | 60% – 90% |
| Collapse | > 90% |

**实测状态转移频率（无干预基线）：**

| 从 → 到 | Healthy | Moderate | Severe | Collapse |
|---|---|---|---|---|
| **Healthy** | 0.67 | 0.33 | — | — |
| **Moderate** | — | 0.80 | 0.20 | — |
| **Severe** | — | — | 1.00 | — |

Severe 态自转移概率为 1.00，说明系统一旦进入 Severe 就**不会自发恢复**，这直接构成了干预必要性的量化依据。

## 六、干预策略

**预算约束：$W = $ 全网总负载的 1%。**

> 这个数字刻意设得很紧。资源充裕时，不同策略的差异会被预算本身抹平，看不出机制上的优劣——只有在资源极度稀缺时，"把钱花在哪"才是真问题。这也更接近应急场景的现实。

**四种策略对比：**

| 策略 | 逻辑 |
|---|---|
| `None` | 不干预（基线） |
| `Opt_Resource` | 按静态拓扑重要性分配资源 |
| `Robust_Resource` | 按容量余量分配资源 |
| **`Adaptive_Neighbor`** | **邻域健康度自适应（本文提出）** |

### Adaptive_Neighbor

**干预优先级：**

$$S_i = d_i \times P_i(t)$$

> 用度乘以失效概率，而不是只看概率。同样的失效风险下，优先救高连通节点——因为它失效引发的二次扩散更广。这是一个**影响力 / 成本比**的取舍：救一个度为 50 的临界节点，等价于救若干个度为 5 的。

**邻域健康度：**

$$H_i = \frac{n_{h}}{n}$$

（$n_h$ 为节点 $i$ 的健康邻居数，$n$ 为邻居总数）

**分支决策：**

- **$H_i > \theta$（邻居健康）** —— 只扩容，扩容量 $EC_i = L_i / H_i$
  邻居有余力接住溢出，所以可以放心把这个节点撑起来；$H_i$ 在分母意味着邻域越健康，扩容量越保守。

- **$H_i \le \theta$（邻居也危险）** —— 扩容 + 同时减载
  $$EC_i = \frac{L_i}{1 - H_i}, \qquad L_i(t+1) = L_i(t)\,(1 - H_i)$$
  邻域自身濒危时，单纯扩容等于把风险原地积压。此时必须**主动卸掉一部分负载**，卸给谁按权重
  $$\omega_{ij} = (C_j - L_j) \cdot R_j^2 \cdot (1 - P_j)$$
  即"余量大 × 响应能力强（平方，强化区分度）× 自身失效概率低"的邻居优先承接。

> **这是整个策略的核心洞察**：干预动作不能是单一的。邻域健康时"加资源"是对的，邻域濒危时"加资源"反而会把节点变成新的引爆点，此时必须**减载**。用一个连续量 $H_i$ 同时控制分支选择和分配强度，避免了硬编码规则。

## 七、关键设计决策与取舍

| 决策 | 取舍与理由 |
|---|---|
| 初始负载引入响应能力 $R$ | 纯度值负载模型忽略"上游供应商多 → 更抗断供"的现实弹性。代价是多了 $\lambda, \mu$ 两个参数，需做敏感性分析（见 §8） |
| 负载重分配分两阶段（下游 + 同层） | 单阶段只往下游推会系统性**高估**级联规模。代价是多一个参数 $\iota$ 和一层计算 |
| 失效判据用任务处理时间而非超载 | 应急场景的本质约束是时间。$T_{\max}$ 有救援文献依据（72h 黄金期收紧至 48h），不是拍的 |
| 波动因子后做归一化 | 引入随机性但保证负载守恒，否则不同策略的结果不可比 |
| 特征里只保留一个动态量 | 强迫模型学结构 × 状态的交互，而不是靠堆动态特征拿到高分 |
| 用 LightGBM 叶节点路径而非预测值作 DNN 输入 | 保留树学到的离散特征交叉信息 |
| 干预预算限定 1% 总负载 | 构造资源稀缺场景，让策略间的机制差异显现 |
| 优先级 $S = d \times P$ 而非只看 $P$ | 影响力/成本比取舍：同风险下优先救高连通节点 |
| 干预动作按邻域健康度分岔（扩容 vs 扩容+减载） | 单一动作在两种邻域状态下必有一种是错的 |
| 失效态设为吸收态 | 符合应急场景（恢复需外部干预）。代价是无法刻画自愈型网络 |

## 八、主要实验结果

### 8.1 级联失效的相变特征

- **临界攻击比例约 5%**：初始定向攻击节点比例超过约 5% 后，最终失效规模出现非线性放大。三种拓扑下该定性规律一致。
- **定向 vs 随机攻击**：定向攻击（按度排序）使最大连通子图（LCC）降至约 **50%**，随机攻击仅降至约 **80%**；定向攻击造成的失效节点数约为随机攻击的 **2.5 倍**。

### 8.2 预测模型性能

**AUC 对比（含噪数据，2000 节点 BA 网络）：**

| 模型 | AUC |
|---|---|
| CatBoost | 0.4836 |
| DNN | 0.5258 |
| LightGBM | 0.6137 |
| XGBoost | 0.6380 |
| **Stacking（本文）** | **0.9622** |

> 这个差距异常之大，我在 §9 中单独说明，**请务必一并阅读**。

**分类指标（Table 6）：** Accuracy 0.9302 · Precision 0.9305 · Recall 0.9305 · F1 0.9305

**过拟合检查：** 5 折交叉验证的训练 / 验证 AUC 差值 **0.0243**。

**拓扑鲁棒性（横向验证）：**

| 网络类型 | Stacking AUC |
|---|---|
| 有向 BA 无标度 | 0.9622 |
| 随机几何网络 | 0.9353 |
| 层级供应链网络 | 0.9250 |

**真实网络验证（纵向验证）：** Willems (2008) 真实供应链拓扑，575 节点

| 指标 | 值 |
|---|---|
| Stacking AUC | 0.9340 |
| Accuracy | 0.9169 |
| Precision | 0.9727 |
| Recall | 0.8768 |
| F1 | 0.9223 |

> 真实网络上 **Precision (0.9727) 明显高于 Recall (0.8768)**，即模型偏向"报出来的基本是真的，但会漏一些"。在应急场景中这个偏向是**不理想**的——漏报一个即将失效的关键节点，代价高于误报一个。真实部署时应下调判定阈值以换取召回，并按误报/漏报的实际成本比重新标定，而不是沿用 0.5。这一点论文中未展开，是我事后复盘意识到的问题。

### 8.3 干预效果

| 指标 | 结果 |
|---|---|
| 失效概率抑制率（PIT reduction） | 约 **80%** |
| 500 节点网络平均存活节点数 | 约 **102** 个（**20.4%**） |
| 层级供应链网络存活 | 26 / 500 |
| 随机几何网络存活 | 6 / 500 |
| 真实网络（Willems）存活 | 32 / 577（**5.55%**） |
| 系统终态 | 锁定在 **Severe**，未进入 **Collapse** |

> **存活率数字差异很大，因为它们属于不同实验设置。** 20.4% 是 500 节点合成 BA 网络在 `Adaptive_Neighbor` 下的结果；5.55% 是真实供应链拓扑下的结果——真实网络的耦合更紧、冗余更少，所以更脆弱。引用这些数字时必须带上对应的网络设置，单独拎出一个百分比是没有意义的。

### 8.4 参数敏感性

对 $x, \lambda, \beta, \mu, \iota, \theta$ 做敏感性分析，**所有一阶敏感性指数 SI < 0.3**，说明结论不依赖某个参数的特定取值，模型行为在参数空间内是稳定的。

## 九、关于 AUC 的必要说明

**这一节是我主动写的，不是别人指出来的。**

基线单模型 AUC 落在 0.48–0.64 区间（CatBoost 的 0.4836 已经**低于随机猜测**），而 Stacking 达到 0.9622。**0.3242 的差距在同一数据、同一特征集上是不正常的。** 融合模型带来提升是常态，但不应该是"从近乎随机到近乎完美"这个量级。

可能的解释有两类：

**① 部分可解释的部分。** 训练时对特征注入了 $\sigma = 0.6$ 的高斯噪声，基线模型在含噪特征上退化明显；而融合模型额外获得了 LightGBM 叶节点路径这一组特征交叉表示，对噪声更鲁棒。

**② 我不能排除的部分 —— 信息泄漏。** 预处理流程为「多项式特征扩展 → KNN 缺失值填补 → 标准化」，这三步都是**从数据中学习参数**的操作。如果它们在训练/测试划分**之前**执行，测试集的分布信息就会通过填补值和标准化统计量渗进训练过程。此外 Stacking 的基学习器与元学习器若在数据划分上存在重叠，元学习器就是在基学习器的**样本内**预测上训练的，这会直接把 AUC 推高到不真实的水平。

**如果重做，正确的做法是：**

1. 把整条预处理管线封进 `sklearn.Pipeline`，作为一个整体在**交叉验证的每一折内部**拟合，测试折只做 `transform`
2. 元特征严格使用 **out-of-fold 预测** 生成，保证元学习器从未见过基学习器的样本内输出
3. 重新报告基线与 Stacking 的 AUC，差距大概率会显著收窄

我认为**收窄后的结果才是这个模型的真实水平**。核心结论（结构 × 状态交互特征优于纯静态拓扑指标；`Adaptive_Neighbor` 优于三个基线策略）建立在策略间的相对比较上，不依赖 AUC 的绝对值，因此不受影响；但"0.9622"这个数字本身，我不会拿它当作模型能力的证据来用。

### 论文文本中的口径问题

一并说明，以本 README 为准：

| 位置 | 论文原文 | 应为 |
|---|---|---|
| 结论段 | "96.22 % accuracy" | AUC = 0.9622；Accuracy = 0.9302（二者是不同指标，不可混用） |
| 结论段 | "32.42 % improvement" | AUC 绝对差值 0.3242，不是百分比提升 |
| Table 6 表头 | "False positive rate" = 0.0698 | 该列实际是**错误率**（$1 - 0.9302 = 0.0698$），非 FPR。正文将其称为 misclassification ratio，表头标注有误 |
| Table 6 | Precision = Recall = F1 = 0.9305 | 三者四位小数完全相同在数学上要求 TP、FP、FN 呈特定巧合关系，可能性极低；**Table 8 的指标集（0.9727 / 0.8768 / 0.9223）内部自洽，应以其为参考** |

**以 Fig.13 与 Table 6/8 的原始数值为准，结论段的表述不严谨。**

## 十、已知局限与下一步

### 局限

1. **训练数据来自本项目的仿真模型，标签由设定的失效规则生成。** 因此高 AUC 反映的是模型对**既定动力学**的拟合能力，**不等价于在真实运行数据上的表现**。这是本工作最根本的局限。
2. 已做的验证是两层的——横向换拓扑（层级供应链、随机几何）、纵向换真实网络拓扑（Willems 2008, 575 节点）。但**换的是拓扑，不是数据生成机制**：真实拓扑上的标签仍然由我的仿真规则产生。
3. **未做**：真实供应链的**运行时序数据**验证。这是唯一能真正检验模型的东西，也是我最想补的一块。
4. 失效态设为吸收态，无法刻画有自愈能力的网络。
5. 真实网络上模型偏 Precision 而 Recall 不足（§8.2），阈值未按应急场景的误报/漏报成本比标定。
6. 干预是逐时刻贪心决策，未做多步最优（可以是一个强化学习问题）。

### 下一步

- [ ] 按 §9 的正确方法重做交叉验证，报告修正后的 AUC
- [ ] 按误报/漏报成本比重新标定判定阈值，优化 Recall
- [ ] 寻找带时序运行数据的公开供应链数据集做真实验证
- [ ] 把逐时刻贪心干预改为序列决策（RL），对比贪心策略的次优程度
